.h3t 模板生成主线

README.md 当前把项目定位为“HoMM3 / HotA 随机地图模板生成器”：把结构化参数转换成 HotA .h3t，纯本地、无 LLM/网络依赖。自然语言意图应先在对话里拆成明确参数，再调用 CLI。

catalog.py 当前包含 22 个生物、11 个神器、1 个特殊对象。任一输入不命中 catalog 会失败退出，不会静默猜测。

输出位置

写入 /Applications/英雄无敌3：二合一.app/Contents/drive_c/game/HotA_RMGTemplates/，骨架模板 Jebus Cross.h3t 当前存在。

已支持写入的字段

  • 模板名与描述：Pack.Name、Map.Name、Pack.Description。
  • 野外守军强度：Zone.Strength，easy/normal/hard 对应 weak/avg/strong。
  • 必出神器：写入 Map.Artifacts，例如 +128 +129。

明确不写入的字段

  • 具体生物：HotA RMG 模板没有“指定某只生物必出”的字段，--creatures 只做 catalog 识别和日志说明。
  • 玩家数：强写 Jebus Cross 玩家字段会导致 HotA 拒绝创建，当前保留给游戏 UI 选择。
  • 地图大小：骨架是 5 zone 设计，强行写 S/M 容易不可加载，当前保留骨架原值。

.h3m 精确注入新增链路

新增链路解决 .h3t 的核心限制：RMG 模板无法保证具体生物出现，而 inject_cli.py 在已经生成的 .h3m 上直接追加对象，因此可以精确放入指定生物和神器。

当前实现

  • h3m/reader.py 只读复用 lib/h3_map_editor 解析 HotA 地图，构建地形、对象、可通行与占用网格。
  • h3m/placement.py 选地表主可达区内的开阔点，避开水、岩、静态对象和不可达孤岛。
  • h3m/sprites.py 维护 catalog 生物 ID 到冒险地图 sprite def 的映射。
  • h3m/inject.py 字节级定位 object attributes / object data section，追加新 attribute 和 instance，再 gzip 写回。
  • inject_cli.py 负责严格解析参数、调用选址与注入，并重新解析输出图做对象数、坐标、类型、地形自检。
